## Questions for the fresh profiles

1. Which type-node fields and graph edges are accessed together? A hot header/cold payload split needs runtime evidence, not just a 112-byte node size.
2. How much work occurs in instancing, signature substitution and repeated graph traversal, including payload clones made through `borrow_desc`? The old `get_desc` census does not cover those clones.
3. Which IR roots remain live across translation, conversion, optimization, export/CMJ and JS generation? A flat store can retain dead generations that recursive ownership previously freed.
4. Does parallel cycle inflation correspond to observable allocation, shared atomic/lock, cache or scheduling costs? If counters are unavailable, leave the cause uncertain.
5. Where can ownership move at a proven phase boundary while preserving all readers, mutations and debug/output behavior?

No source establishes that a larger patch itself improves performance. A larger refactor is justified only if it targets substantial measured work and has a credible native-semantic contract.

## Corrected OCaml source study

Read-only reviewer `bks-045c91ac-0fff-7356-8306-c1f4d4770235` proposed native copy frames, whole-component construction and indexed IR ownership. Parent source checks required these corrections before using the recommendations:

- **OCaml has a real Lambda-to-Lam stage.** `compiler/core/js_implementation.ml:160-166` calls `Translmod.transl_implementation`; `compiler/core/lam_compile_main.ml:278` invokes `Lam_convert.convert`. `compiler/core/lam_convert.ml:357-660` handles alias/exit maps, optional parameter names, FFI, exception wrapping, dependency collection and smart constructors. Rust `raw_lambda/lower.rs` ports that stage. Storage can change, but this logical transformation cannot be deleted or moved earlier merely because the two enum trees resemble one another. The reviewer's original contrary claim was retracted.
- **Snapshot frontier rules differ by object kind.** `compiler/ml/btype.ml:631-650` filters type descriptor/level writes by allocation ID. The mutable-cell setters at `650-665` log through `log_change` without that frontier check. Post-snapshot cell allocation can survive while subsequent cell mutation rolls back. A journal must not treat all cells like type nodes.
- **Copy cleanup is not speculative rollback.** `compiler/ml/ctype.ml:725-865` uses transient `Tsubst` markers and row-more tuples; `instance`/`instance_list` at `865-887` call `cleanup_types`. These lifetimes and mutation rules need separate treatment from Btype backtracking. Moving a saved descriptor does not automatically remove payload copies needed for independent destination ownership.
- **Historical phase numbers are not current D.** The 8.095/8.856s typecheck and 2.393/2.634s Raw figures came from older A/B probes. Fresh A/D measurements must decide current weight.
- **Some apparent opportunities are already measured recoveries.** Historical mutation journaling improved a focused 63.5ms benchmark to 2.6ms but left full Tella roughly flat. Direct contiguous portable internalization had a measured roughly 30ms parallel gain. Both remain relevant mechanisms, but neither should be presented as a new, untested large win.

## Candidates awaiting runtime attribution

- Native transient `Tsubst` copy frames in place of per-instance identity/row-marker hash maps. Audit generic duplication, partial forgetting, GADT registration, abbreviation independence, row/kind sharing, error cleanup and exact allocation order.
- One final component image built at the mandatory whole-component force boundary. Keep module-declaration, child-component and modtype thunk/cleanup lifetimes distinct, preserve evolving captured Env and probe-versus-force behavior. Measure whether eagerly filling complete tables increases work on large signatures.
- Hot/cold or tag/payload type-node storage, selected from access and lifetime evidence. Preserve identity handles and mutation semantics without new per-node reference counting.
- Indexed ownership across the real Lambda-to-Lam stage and later passes. Preserve the transformation order and release input storage at the correct boundary; measure live roots and dead-generation retention before resuming any indexed work.

These are hypotheses, not an implementation selection or predicted speedups. M6 remains paused. Parent will reconcile them with the benchmark owner's fresh diagnostics before assigning one bounded implementation.
