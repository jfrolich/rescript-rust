# Opt-in oxc printer parity (S1.3)

Default invocations of the three output suites still use their original exact
legacy-printer comparisons. Opt into the oxc printer with either interface:

```sh
scripts/test_js_output_parity.sh --printer oxc
PARITY_JS_PRINTER=oxc scripts/test_stdlib_output_parity.sh
GENTYPE_PARITY_WITHOUT_TELLA=1 scripts/test_gentype_output_parity.sh --printer oxc
```

`--printer oxc` implies reformat comparison. The suites use the existing S0
`js-reformat` tool with `--split-file --drop-decoration-comments`; raw JavaScript
is compared by reformatting both sides. Its verbatim-byte and masked-fixed-point
checks remain in `compiler-rust/tests/oxc_printer_oracle.rs`, not in these scripts.
Nothing changes the compiler's default printer or the reformatter's rules.

The alternate runner (`test_printer_parity.py`) clean-builds each project with
OCaml and oxc, inventories newly generated outputs, then compares whole snapshot
trees in one reformatter process. The JavaScript suite also runs the existing
focused fixtures. The genType suite additionally compares generated TypeScript
byte-for-byte and runs its original generation/typecheck suite. TypeScript in
`tests/tests` is not a JavaScript-suite input (as with the existing legacy suite).
In-repository tracked generated files are restored from their actual pre-run
contents, including uncommitted changes. Build artifacts are not restored; as
with the other parity scripts, rebuild OCaml reference artifacts before running
compiler tests that need them.

Oxc mode requires a full corpus: filtered/quick runs cannot update or satisfy a
coverage baseline. `--release` (or `RUST_TARGET=release`) selects the shipping
build. The runner uses `REWATCH_BIN`, `OCAML_BSC`, `RUST_BSC`, and
`PARITY_REFORMAT_BIN` overrides when supplied. Without a reformatter override it
builds the tool once; CI should download the tool alongside the compiler rather
than compile it in each parity job. Output and comparison times are printed.

## Coverage and ratchet

`RESCRIPT_JS_PRINTER_STATS=<directory>` enables immutable JSON reports from the
actual oxc attempts, with source path, generated output path, emitted/fallback
status and reason. Normal builds write nothing. The collector intersects these
reports with files actually generated by that build and counts each output path
once (both ESM and CommonJS count; repeated attempts do not). If any attempt for
one output falls back, that output counts as a fallback. An empty report set or a
legacy-only build cannot satisfy the mandatory positive emitted count.

The in-repository ratchet scopes source paths to the corpus, excluding external
linked dependency sources, while all generated files including dependencies are
compared. For example, tests/tests compares 717 JavaScript files but its ratchet
covers 711 local outputs. Coverage is not the number of `.res` files, nor the
number of compilation invocations. Report failures are visible, and the gate
fails on absent outputs, a lower emitted count, a new fallback reason, or an
increased count for an existing reason.

The baseline is `compiler-rust/tests/printer_coverage.json`. Update each corpus
only after reviewing its successful comparison and printed coverage:

```sh
scripts/test_js_output_parity.sh --printer oxc --record
scripts/test_stdlib_output_parity.sh --printer oxc --record
GENTYPE_PARITY_WITHOUT_TELLA=1 scripts/test_gentype_output_parity.sh --printer oxc --record
python3 -m unittest discover -s scripts -p test_printer_parity_test.py
```

`--record` never records the external corpus. `.parity-cache/printer` holds the
latest local coverage/timing summaries and comparison logs; these are not
committed and may contain private paths when used with a private corpus.

## Source maps

The three current in-repository project configurations do not request source
maps. Separate source-map tests exercise them today; these suites must not
silently replace those gates. Oxc parity sets
`RESCRIPT_JS_PRINTER_SOURCE_MAPS=legacy`, which forces any source-mapped output
onto the legacy printer with the explicit reason `source maps: parity legacy
policy`. Non-JavaScript output, including map files, is compared byte-for-byte.
Without that opt-in variable, existing source-map emitter behavior is unchanged.

## External application comparison

```sh
python3 scripts/test_printer_parity.py --suite external --target release --project APPLICATION
```

This uses the same Rust binary with `RESCRIPT_JS_PRINTER=legacy` and `oxc`, not
an OCaml reference. It reuses `bench_project`'s source-only runtime/Belt package
preparation, follows linked packages once, and inventories newly generated
outputs. JavaScript is batch-reformatted; TypeScript and maps are exact. It
prints the coverage even if comparison fails. The whole project, including its
private dependencies, is counted; generated TypeScript is reported separately
from the outputs handled by the JS printer. The corpus is left candidate-built,
as with `bench_project.sh`. No external data belongs in the baseline or a PR.
