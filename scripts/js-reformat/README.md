# js-reformat

Standalone JavaScript output normalization and comparison using OXC 0.158.0.
This does not change the compiler or wire normalization into CI.

```sh
cargo build --manifest-path scripts/js-reformat/Cargo.toml
cargo test --manifest-path scripts/js-reformat/Cargo.toml
scripts/js-reformat/target/debug/js-reformat format reference normalized
scripts/js-reformat/target/debug/js-reformat compare reference candidate
scripts/js-reformat/target/debug/js-reformat compare reference normalized --candidate-formatted
scripts/js-reformat/target/debug/js-reformat check normalized
```

All commands accept `--strip-comments`. Files with lowercase `.js`, `.mjs`,
`.cjs`, and `.jsx` extensions are visited recursively in sorted relative-path
order; other files and symlinks are ignored. Even `.cjs` files are parsed as ES
modules with JSX enabled, not as CommonJS scripts. Parentheses are not preserved
by the parser (`preserve_parens: false`); codegen inserts precedence parentheses.
All other parser and codegen options are defaults.

`format` creates matching relative paths, overwrites matching output files, and
leaves unrelated output files alone. Prefer a separate output tree outside the
input tree (in-place formatting is supported, but overwrites originals).
`compare` checks the union of paths, reports missing files or the first differing
line (1-based), and shows both lines as escaped strings so newline differences
are visible. `--candidate-formatted` compares candidate bytes verbatim, without
parsing or stripping their comments: use the same options when preparing them.
`check` formats each input twice in memory and compares those two results.

Exit statuses: 0 for success, 1 for differences/missing files/non-fixed points,
2 for parse diagnostics, I/O failures, or invalid arguments. Errors take
precedence over differences. Summaries count failed paths, not diagnostics;
`check` includes failures to parse the second pass. Such failures are reported
as failures rather than byte-level non-fixed points. Empty trees succeed.

## Comments

Default OXC codegen preserves statement-level comments, including this exact
ReScript header and an end-of-file block note:

```js
// Generated by ReScript, PLEASE EDIT WITH CARE
const x = 1;
/* No side effect */
```

The integration test verifies this output byte for byte. OXC's default options
also enable JSDoc, annotation, and inline legal comments, but do not promise to
preserve every comment in every expression position. This is normalization,
not a lossless source formatter. `--strip-comments` uses
`CommentOptions::disabled()` (normal, JSDoc, annotations, and legal comments
all disabled), leaving `const x = 1;` and a final newline in the example above.

## Repository corpus check

Measured with the debug binary using `/usr/bin/time -p`, with comments enabled:

| Tree | Files | Parse failures | Byte-level non-fixed points | Wall time |
| --- | ---: | ---: | ---: | ---: |
| `tests/tests/src` | 718 | 2 | 0 | 0.26 s |
| `packages/@rescript/runtime/lib` | 226 | 0 | 0 | 0.05 s |

`directives.mjs` fails the initial parse (expected semicolon).
`jsx_preserve_cases.mjs` parses initially, but its reformatted JSX fails the
second parse (comma operator in a JSX expression). Thus only 716 test-tree
files successfully complete the fixed-point check; the two failures are not
claims of successful normalization. Neither existing fixture is modified.
